# MAINT-37: Risks & Gaps

## Critical Risks

### Risk 1.1: TARGET-10 Phase 4 does not land, and the motivating corpus stays unpinned
- **Impact**: MAINT-37-07 cannot be delivered; the feature stays `in_progress` with zerobrane's
  `wx` bucket still in its baseline.
- **Likelihood**: medium. TARGET-10 is `in_progress` with only Phase 0 done; its Phase 4 is gated
  on its own Phases 1–3b, DR-03 (repository owner) and DR-08, and is an outward publication that
  needs maintainer confirmation.
- **Mitigation**: the plan orders every TARGET-10-independent phase first (Phases 0–4 here, with 3b), so the
  mechanism, the attribution harness and the busted pins ship without waiting. Phase 5 is a pure
  data change plus one attribution pair once `wxlua` is catalogued.

### Risk 1.2: A GitHub archive repack blocks the fetch
- **Impact**: `fetch-corpus.py` refuses the download; no sweep can run until resolved.
- **Likelihood**: low, and measurable. GitHub generates `/archive/<sha>.tar.gz` on demand; TARGET-08
  chose ADVISORY verification in production for exactly this reason (`LuaDefinitionLibraryFetcher.kt:149-163`).
  Executed 2026-10-10, both pinned archives still match the catalog byte-for-byte (the catalog file
  was last changed in `0c1daa37`, 2026-08-04):
  ```
  $ curl -sSL -o busted.tar.gz https://github.com/LuaCATS/busted/archive/5ed85d0e016a5eb5eca097aa52905eedf1b180f1.tar.gz
  $ curl -sSL -o luassert.tar.gz https://github.com/LuaCATS/luassert/archive/d3528bb679302cbfdedefabb37064515ab95f7b9.tar.gz
  $ sha256sum *.tar.gz; stat -c '%n %s' *.tar.gz
  c33499e7be61511ac48f4815777c3df55322d0ee61fd92c223921999e5543ce8  busted.tar.gz
  236ee34400c553924803a0ce155d3b7d6f0fe4e5577f5eb34b91f96e9f42cea5  luassert.tar.gz
  busted.tar.gz 2040
  luassert.tar.gz 7965
  ```
  Those are the catalog's `sha256`/`size` for both entries.
- **Mitigation**: the refusal text (design §3.7) prescribes the check — extract both, `diff -r`. If
  the trees are identical, updating the catalog's `sha256`/`size` is a production-data change made in
  its own commit; if not, the upstream commit was rewritten and the pin is a TARGET question.

### Risk 1.3: Library globals collide with project names
- **Impact**: busted declares `file`, `spec`, `test`, `context`, `done`, `async`, `expose`; luassert
  declares `match`, `mock`, `stub` (requirements → MAINT-37-06). A project local of the same name may
  start reporting as shadowing, and an assignment to one may change `LuaGlobalCreation`. Whether
  those inspections consult library globals has not been executed.
- **Likelihood**: medium.
- **Mitigation**: the classifier separates these as `TRIAGE-GLOBAL` (every rising symbol is a
  library global), records them, and does not block. They are the correct behaviour of an IDE with
  busted enabled, which is the configuration the sweep is meant to measure.

### Risk 1.4: wxlua contracts raise type-inspection counts
- **Impact**: `LuaTypeAssignability` / `LuaReturnTypeMismatch` rise on zerobrane when `wxlua`'s
  `@param`/`@return` contracts become checkable — TARGET-10's own Risk on the ~10,000 emitted contracts.
- **Likelihood**: high, by TARGET-10's analysis.
- **Mitigation**: `TRIAGE-CONTRACT` rows are recorded with symbol evidence and each inspection id
  with a positive delta gets one BUG, linked to TARGET-10. The pin is not withheld: measuring that
  population on a gate is what TARGET-10's risk register asks of this feature.

### Risk 1.5: The shared definition cache root
- **Impact**: `defaultCacheRoot()` is per user and shared by every test class in the JVM;
  `TypeElevenDefinitionLibraryTestCase` seeds trees there under real catalog ids. A leftover tree
  would be taken as cached and indexed instead of the real archive.
- **Likelihood**: low (TYPE-11 deletes in `tearDown`), but silent if it happens.
- **Mitigation**: `provision` deletes each target directory before extracting (design §3.3, TC 10),
  and `release` deletes after.

### Risk 1.6: Members swept after a pinned member move in the full-shape record
- **Impact**: the committed baselines are recorded in the full (`*Corpus*`) shape, while the
  classifier attributes the member-alone delta. In the full shape every pinned member's `release`
  fires the settings broadcast immediately before the next member, and BUG-418 measured that
  cross-member JVM state shifts counts by a few. Such a movement would be committed with no
  attribution.
- **Likelihood**: medium.
- **Mitigation**: Phase 3b removes the leaked `sourcePath` (design §3.10) first. Every re-record then
  runs the record sequence (implementation-plan → Phase 4), whose reconciliation (design §3.11)
  bounds and labels the shape offset on every member and blocks on what a shape cannot cause.
- **Unconfirmed lead: zerobrane's `unresolvedRequires` depends on the invocation shape.** During
  TYPE-12's planning, a zerobrane-alone run reported `unresolvedRequires` 19 against the full-shape
  baseline's 3. Reported, not confirmed: the log
  (`$HOME/.cache/claude-scratch/lunar/6726d4f8/type-12/run7.log`) shows
  `./gradlew test -PwithCorpus --rerun --tests *LuaCorpusSweepTest.testZerobraneCorpus* --tests *Type12ProbeTest*`
  on the libvirt builder, on a TYPE-12 working tree with a second test class in the same JVM, ending
  `testZerobraneCorpus FAILED` / `java.lang.AssertionError at LuaCorpusSweepTest.kt:101` /
  `BUILD FAILED`; the assertion message holding the figures is not in the log. Not established:
  whether it reproduces on `main`, and what causes it. The plan already specifies both places it
  could surface: Phase 3b's re-record of zerobrane, which may move any zerobrane key and records the
  diff in BUG-496's report; and S2b's offset check (DR-08), where `unresolvedRequires` is a structural
  key, so an offset of that size stops the sequence under DR-08's structural-row branch.

### Risk 1.7: The settings broadcast moves a count for a reason other than the library
- **Impact**: if only one arm received the settings refresh (reload, stub rebuild, daemon restart,
  resolve-cache drop), its effect on any inspection other than `LuaUndeclaredVariable` would classify
  as a non-blocking `TRIAGE-*` row and be recorded as a library effect.
- **Likelihood**: measured per member on every first pin (design §3.11 step 4, "refresh effect").
- **Mitigation**: both arms receive the same refresh (design §3.12), the classifier refuses a pair
  whose observed refresh differs (design §3.5 rows c and d; TC 24, TC 36–38), a refresh missing from
  both arms is stopped at `setUp` (design §3.13), and DR-04 stops on a non-deterministic one.

### Risk 1.8: The startup activity has not finished creating the subscriber when `requireSettingsSubscriber` runs
- **Impact**: with no `LuaSettingsChangeListener`, both arms publish to no one and observe the same
  tuple, so the classifier's equality check would pass a pair with no reload in it.
- **Likelihood**: low (DR-09b, DR-10), but no platform contract this feature can cite guarantees the
  order.
- **Mitigation**: `requireSettingsSubscriber` (design §3.13) fails `setUp` loudly.

### Risk 1.9: The baselines do not reproduce on CI's machine
- **Impact**: the builder records and gates the baselines, but CI's `corpus` job
  (the `corpus:` job of `.gitea/workflows/build-plugin.yml`, `:295-397`) gates them on a `lunar-ci` VM. A phase green on the
  builder can be red there; the job's own comment records one such failure (penlight, run 9733).
  With pins, the CI VM also fetches and extracts the definition archives itself.
- **Likelihood**: low per run (DR-12).
- **Mitigation**: every phase that touches the corpus (0–5) exits only on its PR's `corpus` job green,
  with a stated branch for red (implementation-plan → Gates; S12 in every record sequence). The job's
  fixture step asserts the definition archives (design §3.14), so a failed fetch fails there by name.

## Design Gaps

None open. Every decision is fixed in [design.md](design.md); the behaviour claims that need
execution are the de-risking tasks below, each with its branch outcomes specified.

## Technical Debt & Future Work

- **TBD: catalog entries for `lfs`, `bit`, `jit`, `winapi`** — the remaining large undeclared
  buckets in luarocks and zerobrane. A TARGET item; this feature pins them the day they exist.
- **TBD: classify a re-pin's version change in one classifier pair.** On a catalog re-pin, the
  classifier attributes the new version's whole effect (bare vs new). Reconciliation takes the
  version change alone from `before` (old pin) to `pinned` (new pin), and reports the old version's
  effect as a "previous pin effect" checked by the library rules (design §3.11 step 4).
  A classifier pair of two pinned arms would label the version change symbol by symbol. It needs
  comparability rules for two library-carrying arms, and it is not needed until a re-pin happens.

## Pre-Implementation De-risking Tasks

**Execution record.** Every run of a DR whose Status below is not `done` writes its provenance into
its log before the run itself, so the "Executed on" SHA in its row is read from the log rather than
inferred. With `<dr>` the row's short id (e.g. `dr04-run1`) and
`SCR=$HOME/.cache/claude-scratch/lunar/maint-37`:
1. `mkdir -p $SCR`
2. `git rev-parse HEAD > $SCR/<dr>.log`
3. `git status --short >> $SCR/<dr>.log`
4. Each of the DR's commands, in order, with its output appended: `<command> >> $SCR/<dr>.log 2>&1`
   — a builder run (`tooling/gce-builder/gce-builder.sh run "…"`), a Python invocation, an `rsync`
   or a `grep` alike (a redirect, never a pipe, so each exit status survives). After each command,
   `echo "exit=$?" >> $SCR/<dr>.log`, so a DR with no JUnit XML still records every outcome.

The row then cites the first line of `$SCR/<dr>.log` as "Executed on", and quotes step 3's output if
it is not empty. Each done row states its own provenance.
